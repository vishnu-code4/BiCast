# BiCAST Trip Persistence, Saved Trips & History Documentation

## Overview

The **BiCAST Trip Persistence and History Engine** enables motorcycle riders to save planned routes, customize journey itineraries, review previous rides, and recalculate stale forecasts. The system strictly separates **persistent user configuration** from **ephemeral calculated results** to prevent stale weather forecasts or outdated route data from being presented as current.

---

## 1. Architectural Principles

### Persistent Trip Configuration vs Calculated Snapshots

```text
┌─────────────────────────────────────────────────────────┐
│              Persistent Configuration                   │
│   • Start & Destination (Normalized Locations)         │
│   • User Intermediate Stops (Ordered Sequence)          │
│   • Schedule (Journey Date, Departure Time, Timezone)   │
│   • Motorcycle Fuel Configuration (km/L, Tank, Price)   │
│   • Trip Name & Status (PLANNED, COMPLETED, etc.)       │
└────────────────────────────┬────────────────────────────┘
                             │
            Pipeline Recalculation Triggered
                             │
                             ▼
┌─────────────────────────────────────────────────────────┐
│              Calculated Snapshots (Transient)           │
│   • Selected Route & Alternatives Geometry              │
│   • 15–30 min Travel-Time Smart Checkpoints & ETAs      │
│   • Route Weather Forecasts & Temporal Matching         │
│   • Transparent Safety Score (0–100) & Weather Alerts   │
│   • Corridor Fuel Station Recommendations & Range       │
└─────────────────────────────────────────────────────────┘
```

1. **Decoupled Persistence**: Saving a trip preserves the user's intended route parameters without requiring external API responses (OSRM, Open-Meteo, Overpass) to succeed.
2. **Checkpoint Isolation**: Checkpoints generated by the route engine are transient calculation artifacts and are **never** persisted as `TripStop` records.
3. **Resilient Dual-Mode Database Layer**: Uses Prisma with PostgreSQL transactions when a database connection is active, with transparent fallback to local file-backed JSON storage (`server/data/trips.json`) for seamless local development and offline environments.

## 2. Trip Lifecycle

Trips progress through clear, deterministic states:

```text
DRAFT ──► PLANNED ──► IN_PROGRESS ──► COMPLETED
  │          │
  └──────────┴──────► CANCELLED
```

- **`DRAFT`**: Incomplete route planning or scratchpad itinerary.
- **`PLANNED`**: Active itinerary with origin, destination, and departure time set.
- **`IN_PROGRESS`**: Actively ongoing motorcycle journey.
- **`COMPLETED`**: Finished ride. Weather snapshots are preserved as historical archival logbook records.
- **`CANCELLED`**: Cancelled ride itinerary.

> [!NOTE]
> A trip does **not** automatically transition to `COMPLETED` merely because its journey date has passed. If departure date is in the past and status is `PLANNED`, its forecast status is flagged as `EXPIRED` prompting the rider to update the schedule.

## 3. Freshness & Stale Data Rules

Because weather forecasts and highway conditions change over time, saved trips feature deterministic freshness evaluation:

| State | Condition | Rider UI Presentation |
| :--- | :--- | :--- |
| **`FRESH`** | Calculated $\le 3$ hours ago AND departure time is in the future. | Green `Fresh Forecast` badge. |
| **`STALE`** | Snapshot is $> 3$ hours old. | Amber `Needs Refresh` banner with one-tap "Recalculate Now" CTA. |
| **`EXPIRED`** | Departure date/time has passed and trip is not `COMPLETED`. | Rose `Expired` banner prompting departure time update. |
| **`UNPROCESSED`** | Trip saved before route calculation or pipeline run. | Neutral `Needs Calculation` badge. |

## 4. Recalculation Pipeline

When a rider clicks **"Recalculate Trip"** or updates departure time:
1. The persistent trip configuration (origin, destination, user stops, motorcycle specs) is loaded.
2. The complete BiCAST engine pipeline executes in sequence:
   $$\text{Route Engine} \longrightarrow \text{Smart Checkpoints} \longrightarrow \text{ETA Matching} \longrightarrow \text{Weather Timeline} \longrightarrow \text{Risk Engine} \longrightarrow \text{Fuel Planning}$$
3. Downstream updates are applied immediately:
   - Checkpoint arrival ETAs shift with departure time.
   - Open-Meteo hourly weather queries match updated arrival hours.
   - Safety score (0–100) recalculates with the latest atmospheric conditions.
   - Recommended fuel stations update open/closed status and estimated arrival tank levels.
4. The trip's `lastCalculatedAt` timestamp and calculated snapshot payload are updated.

## 5. Duplication & Cascading Deletion

- **Duplicate Trip (`POST /api/trips/:tripId/duplicate`)**:
  - Clones all trip parameters and creates **completely independent copies** of intermediate stops.
  - Modifying stops on the duplicated trip has zero effect on the original.
  - Default naming convention: `[Original Name] Copy`.
- **Delete Trip (`DELETE /api/trips/:tripId`)**:
  - Cascades deletion using Prisma transactions to remove associated `trip_stops`, `weather_snapshots`, and `weather_alerts`.
  - Guarantees zero orphaned database records without purging global route or weather caches.

## 6. Frontend Navigation & Mobile Features

- **`/saved-trips`**: Responsive grid of saved trips with search, status filtering (`All`, `Planned`, `Drafts`, `Completed`), and sorting (`Newest`, `Oldest`, `Journey Date`).
- **`/trips/:tripId`**: Dedicated trip dashboard with stale forecast banner, interactive recalculation, inline schedule editor, and itinerary breakdown.
- **`/history`**: Rider logbook with lifetime statistics (total rides, completed, planned, total km).
- **`/plan?editTripId=:tripId`**: Preloads saved trip parameters into the trip planner for interactive route editing and stop reordering.
